# 🚀 100 Days JavaScript Learning Journey

> A 100-day, problem-driven journey to build strong JavaScript fundamentals, develop programming logic, understand data structures and algorithms, and eventually use JavaScript confidently in real-world applications and the MERN stack.

## 🎯 Goal

The goal of this journey is **not simply to learn JavaScript syntax**.

By the end of 100 days, I should be able to:

- Write JavaScript naturally without constantly checking syntax.
- Solve programming problems independently.
- Break unfamiliar problems into smaller steps.
- Understand and manipulate arrays, objects, strings, and other data structures.
- Understand important JavaScript concepts deeply.
- Debug my own code confidently.
- Understand basic algorithmic thinking and complexity.
- Write clean and maintainable JavaScript.
- Use JavaScript effectively when building real applications.
- Have a strong foundation for React, Node.js, Express.js, and the MERN stack.

---

# 🧠 Problem-Solving Method

For every programming problem, follow this process:

## 1. Understand

Ask:

- What are the inputs?
- What is the output?
- What exactly is being asked?

## 2. Identify Concepts

Determine which JavaScript concepts are involved.

Example:

```text
Array
+
Loop
+
Condition
+
Counter
```

## 3. Solve Manually

Explain how you would solve the problem without code.

## 4. Write the Algorithm

Convert your thinking into simple steps.

## 5. Implement

Write JavaScript.

## 6. Test

Try:

- Normal input
- Small input
- Empty input
- Boundary cases
- Unexpected input when relevant

## 7. Debug

Understand **why** something failed.

## 8. Review

Ask:

- Is the code readable?
- Is the logic correct?
- Can it be simplified?
- What are the trade-offs?

## 9. Complexity

Eventually determine:

- Time complexity
- Space complexity

## 10. Reflect

Ask:

- What did I learn?
- What mistake did I make?
- Why did I make it?
- How can I recognize this pattern next time?

# 📌 Rules for This Journey

### Rule 1 — No rushing

Understanding is more important than finishing a problem quickly.

### Rule 2 — Search independently

When stuck, I should:

1. Identify what I don't understand.
2. Search/read documentation or explanations.
3. Experiment.
4. Return to the problem.

### Rule 3 — Don't memorize blindly

Always understand:

```text
What?
Why?
How?
When?
```

### Rule 4 — Learn from mistakes

A bug is not wasted time if I understand why it happened.

### Rule 5 — Gradual difficulty

Problems should be challenging enough to make me think, but not so difficult that I cannot make progress.

### Rule 6 — Build for the future

The JavaScript learned here should eventually support:

```text
Frontend
React
Backend
Node.js
Express.js
APIs
Databases
MERN Stack
```
